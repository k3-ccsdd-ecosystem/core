# ブランチ・コミット・Issue・PR

- 段階の作業は作業ブランチ `stage-<段階番号>`（例: `stage-1`）で行う。無ければ main の最新から作る。main に直接コミット・push しない
- コミットは小項目ごと。メッセージは「`<type>: <要約>`」で、小項目の成果物は「`docs: <小項目 ID> <成果物名>`」（例: `docs: 1-6 制約一覧`）。判定記録は「`docs: GATE-<n> 判定記録`」
- `git add` はコミットするファイルを指定する（`git add .` や `git add -A` を使わない）
- Issue のタイトルは「`<ID>: <要約>`」。本文に、背景、依頼内容、参照（リポジトリ、パス、コミット）を書く
- PR のタイトルは、判定の PR なら「`GATE-<n>: <判定名>`」、それ以外は「`<ID>: <要約>`」。本文に概要、確認したこと（gate-checker の結果など）、`Refs:` の行（その PR が作る・変える・満たす ID を半角スペース区切りで）を書く
- PR のマージは人が行う。`gh pr merge` を実行しない
- force push（`-f` とその結合形、`--force`、`--force-with-lease`、`+<ref>`）をしない。履歴を書き換える必要が出たら人に相談する
- リモートブランチを消さない（`--delete`、`-d`、`:<ブランチ>`）。マージ後のブランチの削除は人が行う
