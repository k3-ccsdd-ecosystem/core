# 成果物の書き方

工程の成果物（`docs/` の下）と判定記録（`gates/` の下）に適用する。段階ごとの成果物の一覧は `.ccsdd/docs/stages/stage-<段階番号 2 桁>.md`。

- 成果物はテンプレート（`.ccsdd/templates/`）を読み、その構成で新しいファイルとして書く。テンプレートのファイルは編集しない
- 節の見出しの文字列を変えない・消さない・順序を入れ替えない（gate-checker は見出しの文字列で節を探す）
- 記入欄 `{{...}}` はすべて置き換える。該当しない節は消さずに「該当なし（理由）」と書く
- テンプレートの HTML コメント（`<!-- -->`）は記入の手引き。書き終えたら消してよい
- 「参照元」の節に、入力にした成果物のパスをルートからの相対パスで `` `docs/…` `` の形で書く。リポジトリの外の入力は「（外部）」「（既存）」を付けて所在を書く
- インプットから導けない事項を推測で埋めない。「未確定」と書き、確定させる人と時期を添える
- 事実には出典を付ける（特に調査メモ）。出典の無い数値や事例を書かない
- 書き終えたら、人が読める体裁（見出し、表の崩れ、文の長さ）、テンプレートへの準拠、抜け漏れをセルフレビューし、gate-checker で確かめる:

```bash
node .ccsdd/gate-checker/dist/gate-check.mjs --stage <段階番号> --no-write
```

- gate-checker の指摘のうち、まだ作っていない小項目の成果物に関するもの（file.missing など）は、その小項目の担当で解消する。自分の小項目の指摘は残さない
