# ID の書き方

正は `.ccsdd/docs/ids.md`。ここには作業中に守る要点だけを書く。

- 形式は「接頭辞-連番」。連番は 1 から、ゼロ埋めしない（`CST-1`。`CST-01` は不可）。受け入れ条件は `US-<n>-AC<m>`、判定記録は `GATE-<段階番号>`
- 接頭辞: `CST` 制約、`PER` ペルソナ、`US` ユーザーストーリー、`SCR` 画面、`API`、`SEQ` シーケンス、`NFR` 非機能要件、`RES` リソース、`SLI`、`ALT` アラート、`THR` 脅威、`TST` 試験、`GATE` 判定記録
- 新しい ID は、その接頭辞で使った最大の連番 + 1。欠番は詰めず、削除した ID は再利用しない
- 定義は ID ごとに 1 か所。Markdown では「見出しの先頭」か「第 1 列の見出しが `ID` の表の第 1 列」が定義、それ以外は参照
  - 参照を並べる表の第 1 列を `ID` にしない。見出しで参照するときは ID を先頭に置かない（`### ジャーニー: PER-1`）
- Gherkin は Feature のタグ `@US-<n>` と Scenario のタグ `@US-<n>-AC<m>` が定義。ペルソナは Feature のタグ `@PER-<n>` で参照する。ファイル名は `US-<n>.feature`
- 範囲の表記（`US-1〜3`）は使わず、`US-1, US-2, US-3` と列挙する
- 他リポジトリの ID も接頭辞と連番だけで書く（接頭辞ごとに定義するリポジトリは 1 つ）。使う ID は入力記録の「参照する ID」に書く
